## 分批协议（每批固定六步，不做例外）

1. **取证**：脚本只做**定位**（引用面、裸 SQL、tenant 列、allModels 登记、路由注册），结论由人写。
2. **判关**：按 4.1~4.4 给每个实体落结论，命中缺陷的进第 3 步。
3. **修**：只做"就地补/下沉/上移/删除"四种动作，不新增抽象层。
4. **验**：`go build ./...` + 受影响包 `go test`；租户相关补 on 模式锁；门禁 `check-gorm-only.sh`。
5. **记**：更新 `model-list.md` 行（不写"已审"这种空话，写证据）。
6. **交**：显式路径 `git add`（**永不 `-A`**，另有并发车道在同一 worktree）→ 提交 → 推双远端。

批次大小：任务一 **10 个实体/批**；任务二 **25 个文件/批**。

## 阶段 A：任务一剩余 134 实体（14 批）

按预检标记优先级排：`T`（无 tenant_id 需论证）→ `U`（未进 allModels）→ `L`（模型越层）→ `N`（动态表名）→ 无标记。

每批产出：实体行 + 命中缺陷的修复 + 该批新增回归用例。

## 阶段 B：任务二 1599 文件（64 批）

先按"含目标注释特征"排序（历史叙事 / 批次号 `R5`·`T-P3`·`B-2` / 门禁插装 / 5 行以上论证），
特征密集的先清。**质量闸**：每个文件改完立即做 AST 等价校验（`go/parser`：去注释后打印两版 AST 比较），
不等价即回滚该文件——这条保证"只动注释"不是靠自律，而是靠机制。

不需要清理的文件记 `[—]` 并写明一句依据（例：仅含功能性注释 / 纯 DTO 无注释）。

## 风险与止损

- 任务二误删承载关键前提的注释：AST 闸只保证不改代码，不保证注释质量 ⇒ 每批随机抽 3 个文件人工复读；若发现"删掉了唯一在讲前提的注释"，立即在该批内恢复并把该特征加入保留规则。
- 任务一大改动撞并发车道文件：只 stage 自己路径；`migrate.go` 这类共享文件用 `git apply --cached` 单独暂存自己的 hunk。
- 全量 `go build ./...` 被并发车道打断：以包级 build/vet 为验收下限，并在报告里点名被谁打断。

# W-9 i18n 渲染断言落地（2026-10-24）

任务（`docs/任务总表-2026-10-24.md` W-9）：现有门只证明「源码里没有硬编码中文」，证明不了「译文真的渲染进 DOM」。本批补第一条渲染腿，并做成可复用样板。

## 1. 挂载点选型

- 组件：`user-web/src/components/SubMenuItem.vue`（侧栏菜单单项，纯展示件）。
- 理由：文案只有一处来源 `{{ t('menu.' + menu.key) }}`；不碰接口/store；key 是命名空间式（`menu.workspace`），与任何译文都不相等 —— 反向对照才有意义（中文 key 词条做不到：key 本身就是译文，正反两向分不开）。
- 词条（`src/i18n/locales/{zh,en}.json` 均存在）：`menu.workspace` = 工作台 / Workspace；`menu.customer` = 客户中心 / Customer Center；`menu.customer360` = 客户 360 / Customer 360。
- 未触碰并行车道文件（`views/KnowledgeWorkspace/KnowledgeManagement.vue`、`src/types/components.d.ts`），未改任何 locale JSON。

## 2. 用例与判据

文件：`user-web/tests/unit/subMenuItem_i18n_render.test.js`。放 `tests/unit/` 是既有约定：`vitest.config.js` 的 `include` 只收 `tests/unit/**`，`src/**/__tests__` 收不到。

zh、en 各挂一次（项目自己的 i18n 单例 + 真实语言包，非 stub），四条判据：

1. **反向对照（第一条跑）**：`w.text()` / `w.html()` 不含 `menu.workspace` —— 模板丢了 `t()` 时这里先炸，报错直接指到病根；
2. DOM 文本 === 磁盘 JSON 里的值（直读文件、绕开 vite 预编译，避免「拿 t() 验 t()」自证）；
3. DOM 文本 === 写死的显示口径（工作台 / Workspace），改译文必须同步改这里；
4. 命中数 = 1（`text.split(literal).length - 1`）；另加分组用例：父标题、子项各 1 次，两个原始 key 都不出现。

## 3. harness 需要什么（可复用样板）

- 依赖齐全、无需安装：`@vue/test-utils`、`jsdom`、`element-plus` 已在 devDependencies。
- `ElMenuItem` / `ElSubMenu` 的 setup 会 inject 根菜单，裸挂会抛 `ElementPlusError: [ElMenuItem] can not inject root menu` ⇒ 用 render 函数套一层 `<ElMenu>`（仓内单测不引运行时模板编译器）。
- 组件内 `t` 取自模块级单例（`i18n.global.t`，非 `useI18n()`）⇒ 用例改 `i18n.global.locale.value` 并在 `afterEach` 还原（与 `chat_embed_avatar_*` 同法）。
- `useRouter()` 要注入：用 `createMemoryHistory` 真路由，不 mock。
